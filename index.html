DSA Concepts & Project Architecture

1. Queue (FIFO)

Role: Captures incoming mathematical characters/tokens from the user input in strictly sequential order.

Principle: First-In, First-Out (Enqueue at rear, Dequeue from front).

Complexity: Time: O(1) per token | Space: O(N)

2. Stack for Infix to Postfix (LIFO)

Role: Temporarily holds operators and parentheses to reorder them based on precedence (^ > * / > + -).

Principle: Shunting-Yard Algorithm. High precedence operators pop before low precedence operators are pushed.

Complexity: Time: O(N) | Space: O(N)

3. Stack for Postfix Evaluation (LIFO)

Role: Scans the postfix string. Digits/numbers are pushed to stack. When an operator is encountered, 2 numbers are popped (b then a), computed, and pushed back.

Principle: Operand evaluation without ambiguity.

Complexity: Time: O(N) | Space: O(N)

4. Doubly Linked List (History)

Role: Stores each calculation with bidirectional links (prev and next pointers).

Advantage: Allows constant-time O(1) insertion at the tail, two-way traversal (oldest-to-newest and newest-to-oldest), and previous/next interactive navigation.

Complexity: Insertion: O(1) | Traversal: O(N) | Space: O(N)

Execution Flow Pipeline:

User Input → Input Queue → Operator Stack → Postfix String → Evaluation Stack → Doubly Linked List Node
